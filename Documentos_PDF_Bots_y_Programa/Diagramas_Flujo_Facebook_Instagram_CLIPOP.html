⚙️ 3. Arquitectura del Webhook Unificado de Meta

Flujo de datos síncrono/asíncrono en Node.js Express, Base de Datos PostgreSQL y API Graph de Meta. 

sequenceDiagram
    autonumber
    actor Cliente as Usuario (FB / IG)
    participant Meta as Meta Graph API
    participant Webhook as CLIPOP /api/webhooks/meta
    participant Dedup as Caché TTL (Anti-duplicados)
    participant DB as PostgreSQL (Prisma CRM)
    participant Agent as agentCore.js + Gemini 1.5

    Cliente->>Meta: Envía mensaje o toca botón
    Meta->>Webhook: POST Webhook (messaging event)
    
    Note over Webhook,Meta: Cumplimiento de SLA: Responde en menos de 500 ms
    Webhook-->>Meta: HTTP 200 "EVENT_RECEIVED"

    Webhook->>Dedup: Verificar mid (Message ID)
    alt Es Duplicado
        Dedup-->>Webhook: Ignorar (Evita mensajes dobles)
    else Es Nuevo
        Dedup->>DB: Registrar Lead y Mensaje Entrante
        alt Bot Pausado (bot_paused = true)
            DB-->>Webhook: Pausado para Asesor Humano (No responder)
        else Bot Activo
            Webhook->>Agent: Evaluar mensaje / Payload
            Agent->>Agent: adaptLinksForPlatform()
            Agent->>DB: Registrar respuesta enviada
            Agent->>Meta: POST /v20.0/me/messages (Send API)
            Meta->>Cliente: Entrega respuesta inmediata
        end
    end
